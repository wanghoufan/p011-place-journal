## 1. 一句话结论

**这个项目从 Day 1 起就不是「习惯养成 / 周期打卡」工具，而是一本「双端私人地点手账」**：拍照 + 说感受 → AI 整理成可筛选记录 → 按地点/标签/时间回顾 → 一句话找地点 → 生成可撤销的私密分享快照。PWA 与 Android 共用同一 Supabase Schema。

因此本报告对任务书中「打卡项定义、周期规则、统计口径、提醒、补卡」逐项给出**真实答案**（§7）：这些概念在产品和代码里**不存在**；存在的只有「到访日期」与「计数式数据统计」。真正的 Day 1 发生在 **2026-09-01**，且**不在本仓 Git 历史内**（首提交 09-03 是基线入库），Day 1 需求真源是 `docs/V1_PRODUCT_AND_TECHNICAL_PLAN.md`（下称 SSOT）。

Day 1 的需求文档整体质量高（一句话定义、P0、明确不做、导航锁定、标签两层、分享白名单、M0–M6、统一验收清单），但漏写了 **6 类决定性规格**，后续 90% 的高频返工都能追溯到这 6 类（§9）：数据生命周期语义、同步协议语义、分享与隐私边界、跨端合同、输入链路与门槛、产品命名身份。

1. **首次打开**：预置 6 个带标注演示地点（`src/lib/demo.ts`、`src/pages/Mine.tsx:130` 显示「演示数据」与「清除演示数据」）。首屏是画廊，不是表格也不是地图（SSOT `:66` 产品原则、`Gallery.tsx:1`）。

## 7. 关键 UI / 操作模式（逐项回答任务书里的「打卡」概念）

| 任务书中的概念 | 本项目真实情况 | 证据 |
|---|---|---|
| **打卡入口** | Web：底部三 Tab（画廊/找地点/我的）+ 正上方悬浮「记录」主按钮，记录不算第四个入口（`src/components/Nav.tsx`、SSOT `:118-121`）。Android：四 Tab（画廊/记录/发现/我的，`mobile/app/(tabs)/_layout.tsx`）。入口唯一且常驻，任何主页都能一步开始记录 | 同上 |
| **打卡项定义** | **不存在**。实体是「地点 Place」+「到访记录 Entry」；一条 Entry = 一个地点的一次到访（`types.ts` Place/Entry） | `src/lib/types.ts` |
| **补卡** | **不存在补卡机制**。只有 `visitDate`（到访日期）可自由填任意过去日期，编辑页也可改（`EntryDetail.tsx:32,90`），效果等价「事后补记」；没有「今天必须打卡」「漏打卡」概念 | `EntryDetail.tsx:90` |
| **周期规则** | **不存在**日/周/月周期、重复任务、连续天数 | 全仓检索无 `streak/周期` 实现 |
| **统计口径** | 只有计数式统计：地点数/记录数/照片数/本机占用/演示条数（`Mine.tsx:130-132`）；浏览侧是相对时间分组（今天/昨天/N 天前/N 周前，`Gallery.tsx:139-146`）与筛选（标签交集、5 档评分、地区/类型/场景）。**无周报/月报/连续打卡/完成率** | `Mine.tsx:130`、`Gallery.tsx:139` |
| **提醒** | **完全没有**。无本地通知、无推送、无定时提醒、无通知权限申请；分享/同步也无系统通知 | 全仓检索无 `notification/reminder` |
| **分享入口模式** | 详情页按钮 → 弹层（复制链接 / 生成长图）；「我的」里管理分享与撤销；Android 走系统 Sheet | `EntryDetail.tsx:117-151`、`Mine.tsx:197` |

**给复盘结论**：如果用户的原始意图确实是「习惯打卡」（每天做 N 次、连续天数、提醒），那这个项目从第一行代码起就跑偏了——但 SSOT、README、首提交信息、09-01 日志四重证据都指向「地点手账」。**真实风险是命名骗了人**（仓库名/项目名「个人打卡小工具」、Schema `habit_tracker`），不是实现跑偏。

1. 读 SSOT + 7 张视觉基准图。
2. 搭工程骨架 + 演示数据（6 地点）。
3. 做完画廊/记录/AI 确认（本地启发式）/找地点/标签/分享页的**全流程假数据可点击版**。
4. 再接入 Supabase（登录、同步、分享 RPC）。
5. 最后接 AI Provider 与地图。

这与 SSOT M0→M6 的顺序一致（`:396-404`），也是本项目实际走通的顺序。

## 11. 可直接复制给计划者的 Day 1 提示词

> 说明：以下整段可直接复制给「计划者/规划智能体」。它用产品语言写需求，不要求用户自己定义数据库 Schema、API 或框架；技术选型由计划者在你给出的约束内决定。

```text
你是这个项目的计划者。请先读完我给的资料，再产出一份可直接开工的 V1 计划；不要先写代码。

【产品一句话】
做一个以手机为主、可安装到桌面的「私人地点手账」：我去一个地方，拍几张照片、把感受说出来，它帮我整理成一条可筛选的记录；以后我能按地点、标签、时间翻回来，用一句话找到「适合带爸妈吃饭的地方」，并把一个地点或一份清单分享给朋友。

【先纠正一个名字】
这个项目不叫「习惯打卡」，也绝不做打卡项、周期、连续天数、补卡、打卡日历或提醒。仓库名和数据库 Schema 里的 habit_tracker 是历史遗留名字，不要据此设计功能。请把「不是习惯打卡工具」写进计划的非目标第一条。

【用户与场景】
用户就是我一个人（personal-use）。核心场景：
1) 到一个新地方，拍照 + 说一句「这家咖啡人均 50，晚上很舒服，适合聊天拍照，4 星」；
2) 系统整理出星级、人均、标签、一句公开理由，我确认后才保存；
3) 过几个月我想找「海口适合拍照的咖啡馆」，用一句话或筛选条件就能翻出来；
4) 我把一处地点或一份「海口拍照清单」发给朋友，朋友能看照片和理由，但看不到我的私密感受。

【页面与入口】
- 底部三个一级入口：画廊 / 找地点 / 我的，视觉对称。
- 「记录」是悬浮在导航正上方的主按钮，不算第四个页面。
- 首屏必须是画廊（照片墙），不能是表格或地图。
- 画廊支持「按记录 / 按地点」双视图；顶部有常用场景筛选；卡片显示相对时间。
- 同一地点多次到访：按记录是三条，按地点是一个地点 + 多次历史。

【记录流程】
1) 选照片（最多 9 张，可换封面）；2) 选已有地点或新建地点（名称 + 区域）；3) 到访日期（可填过去的日期）；4) 人均预算（可空）；5) 「说说你的感受 · 仅自己可见」一个大输入框，支持用微信语音输入法直接说，写多少装多少；6) 「公开分享理由」选填，单独一框。
7) 点下一步进入 AI 确认页：AI 给出星级、预算、整理后的感受全文、公开理由、命中的已有标签、未命中的建议词；所有字段我都能改；我点保存才入库。
8) 缺地点或缺内容时，主按钮要禁用，并且按钮文案直接告诉我还缺什么。
9) 断网也能保存，先存本机，联网后自动同步；杀进程后草稿（含已选照片）不能丢。

【标签】
我可以用 20–80 个自定义标签建立自己的判断体系。维度包括地区、类型、场景、人群和自定义；常规标签只允许「父 → 子」两层，父标签只是分组，记录只挂叶子标签；标签可改名、可删除、可看使用次数；筛选时选父标签要包含它下面的子标签记录。

【找地点】
一个自然语言输入框 + 条件筛选：星级 5 档、标签（按维度分组、多个条件取交集）、地区/类型/场景；已选条件要显示成可取消的 chips；结果可切清单视图或画廊视图；可以从结果里勾选若干条生成一份清单分享。

【分享与隐私（红线）】
- 分享必须是「快照」，只包含白名单字段：封面展示图、地点名、区域、星级、人均、公开理由、公开标签、粗略坐标。
- 绝不带出：私密感受原文、语音、完整到访历史、未选的照片、原图 EXIF、精确坐标。
- 分享链接不需要登录即可打开，但不能被搜索引擎收录，也不能被别人枚举；我可以随时撤销，撤销后链接必须立刻失效。
- 分享链接要能生成一张长图，因为微信里外链经常被拦，我要能直接发图。
- 单地点分享和多地点清单分享两种；清单可以有地图总览，地图只显示我允许分享的点位。

【数据与同步（用行为描述，不要我定技术方案）】
- 本地优先：先写本机，再同步云端；同步状态要能看见（未同步/同步中/已同步/失败/冲突），并显示待上传条数和上次同步的成功/失败数。
- 同一账号换设备能看到同一批记录；别人绝对看不到我的数据。
- 重复同步不能产生重复记录；删除必须真的删掉云端那份，而且不能被后台拉取「复活」。
- 如果我在两台设备上同时改了同一条，要让我选「用云端 / 保留本地 / 手动合并」，不能静默覆盖我刚存的内容。
- 演示数据永远不能上传到云端，并且我能一键清除演示数据。
- 我能导出自己的数据（JSON 和 CSV，含媒体清单）。

【其它必须有的】
- 详情页：点图放大、左右滑、显式按钮设封面；可编辑地点/星级/日期/人均/感受/公开理由/标签；地点改名对所有该地点记录生效；可把记录搬到另一个地点。
- 删除要有应用内确认弹窗。
- 主题：网页至少三套配色，安卓支持浅色/深色/跟随系统，切换不能丢业务状态。
- 安卓端同构：同一账号、同一批数据，分享走系统分享面板。

【明确不做】
不做公开社区/关注/点赞/评论/榜单；不做交易团购订座；不做原图云盘；不做定位轨迹或自动记录；不做 AI 生成假地图；不做 AI 自动建标签；不做协作编辑；不做习惯打卡的任何东西。

【技术约束（这些是已定事实，不要改）】
- 复用我现有的共享 Supabase 项目（Project Ref 我会单独给你），用独立 Schema 与独立 Storage 桶隔离；表结构、RLS、桶策略你来设计，但我要求：匿名访客只能按分享 slug 读取一张有效快照，不能读表。
- 登录用 Google（Supabase Auth）。
- 部署用 GitHub + Vercel；地图用高德 JS API；AI 整理走可切换的 Provider 适配层（OpenRouter / DeepSeek / OpenCode），模型和 Key 用环境变量注入。
- 任何密钥都不得进入代码仓库或前端包。

【交付节奏】
先给我 M1：全部页面用假数据可点击走通（画廊/记录/AI 确认/找地点/标签/分享），视觉对照我给的 7 张基准图；确认后再做登录、本地库、同步、分享快照，最后接 AI 与地图。
每一阶段结束给我：做了什么、怎么验证的（截屏或日志）、还剩什么风险。不要用「已配置」代替「已验证」。

【验收】
请同时产出一份验收清单，至少覆盖：首屏是画廊；三入口对称且记录随时可达；多图与换封面；按记录/按地点两种视图；标签两层与父含子；断网可记录且联网自动同步不重复；删除不复活；两用户互相读不到数据；前端包无服务端密钥；AI 必须先确认再入库；分享页不含私密字段；撤销后链接失效。
```
